# 秘密値の扱い

秘密値を検査する範囲を決めるとき、別の端末や作業者へ秘密値を受け渡すとき、作業ツリーを退避したり写したりする前に読む。

## 検査するのは、Gitに入り得るファイルだけにする

秘密値の検査（gitleaksのような道具）は、Gitに入り得るファイルの集合を対象にする。その集合は、Gitが追跡しているファイルと、まだ追跡していないが無視の設定にも当たらないファイルを合わせたもので、`git ls-files --cached --others --exclude-standard` で得られる。directoryをまるごと走査すると、無視の設定で守られた手元の正当な置き場（`.env` など）まで検出し、検証全体が止まる。新しい端末で秘密値を置いたとたんに検証が通らなくなるのは、この形である。

除外は、ファイルの集合を絞る形で書き、検査の道具の許可リストでpathを外す形では書かない。許可リストはGitの履歴の走査にも効くので、そのpathに過去に入った秘密値まで見逃すからである。

## 受け渡す束は、検証が読む設定の一覧から作る

別の端末や別の作業者へ秘密値の一式（束）を渡すときは、束に入れる設定を記憶から選ばない。repositoryの完了判定のcommandと、E2Eのような外部につなぐ検証が読む設定の一覧を先に作り、束がその一覧をすべて含むことを確かめる。束から戻したファイルだけで、完了判定とE2Eの前提が揃うかを、戻した後に確かめる。一覧に無い設定を検証が読んでいたと分かったら、束と一覧の両方に足す。

## 退避と写しの前に、無視されたファイルを巻き込まないかを確かめる

作業ツリーを退避する操作には、無視されたファイルまで含めるものがある（stashの `-u` や `-a`、作業ツリーを丸ごと写すコピー）。実行する前に、無視の設定で守られた秘密値が対象に入らないかを確かめる。入るなら、秘密値を外した形で退避するか、退避をやめて利用者に委ねる。

保全のために何かを写すときは、写す先を選ぶ。一時領域（`/tmp`、セッション専用の作業領域）は、再起動やセッションの終わりで消える。失いたくない変更は、Gitの参照（branchやtag）か、利用者の永続的な領域に保全する。秘密値を含むものは、そのどちらにも置かず、利用者の秘密値の置き場へ戻す。

## 判断例（図書館の貸出）

図書館のsiteのrepositoryは、外部の認証サービスの鍵を無視の設定で守った `.env` に置き、E2Eでは共用のテスト用利用者の一覧を別のファイルから読む。検査の道具にdirectoryを走査させると `.env` を検出して止まるので、Gitに入り得るファイルの集合だけを渡す。新しい端末へ秘密値の束を渡すときは、完了判定とE2Eが読む設定の一覧から束を作る。認証の鍵だけを入れてテスト用利用者の一覧を忘れると、新しい端末ではE2Eが動かない。
